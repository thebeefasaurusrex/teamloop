## A separate workflow, not replacement history

The original brief, seed data and six-category rubric stayed frozen. Each practical configuration had 45 minutes total, at most 32 intentional host turns and four sequential file actions per turn. Every native call used the remaining total deadline rather than restarting the clock. Native effort labels are not equal compute.

Only the trusted host applied selected Read/Write/Edit requests. Two task documents were immutable; only the HTML and progress note were writable. Native operational tools, Compute, OS commands, browser, network, MCP, delegation and adaptive lead QA feedback were absent. Prior complete actions/results were replayed on each intentional host turn. This is explicit host-transcript orchestration, not native session continuity or automatic continuation. HTML remained capped at 512 KiB; full native prompts and capture were bounded without silently truncating them. It is a constrained cooperative service, not proof of hostile same-user OS isolation.

The new cohort remains separate from the earlier one-shot and other file-backed studies. Same product brief does not make different tool and continuation workflows interchangeable. The study-local controller is not installed as a new automatic production route.

## What worked, and what did not

Both artifacts started without observed runtime exceptions. Core checks covered all four fictional records, failed-candidate exclusion, live scoring, filter/selection restoration, notes and score association through an Enter-key swap, and comparison changes. The objective check evidence and original reviewer score remained separate from edited assessment values. Viewport checks reported no horizontal page overflow at 1440x900 and 390x844.

Opus explicitly says missing evidence details were not supplied. Argon instead invented per-record validated gate logs, a specific accessibility finding and a category decomposition of an aggregate reviewer score that the brief never provided. After the selected pair changed, Argon's verdict labels still named the original records while a routing value referred to the current right-side record. Its decision meaning was therefore ambiguous. After the score lock, root confirmed the source-derived bounds defect in the actual UI: entering 100 in all five categories displayed **500 / 100**, with no invalid flags. The locked score was not changed.

Opus also retained a smaller clarity issue: a draft score of 99 stayed visible and invalid after blur while the internal criterion contribution clamped to 10. Neither artifact is an exhaustive product certification.

Both apps reported a download, but the actual downloaded JSON files were not inspected. The browser download observer timed out; a blocked browser URL was not bypassed. Argon's visible JSON preview preserved selected IDs and edited scores, but that does not verify the downloaded file. This observation limit is not an established app failure. Full keyboard, screen-reader and cross-browser audits remain unverified.

The initial telemetry-setting and physical-workspace setup refusals made zero inference calls. Narrow privacy restoration and a verified physical workspace corrected preparation without weakening the strict guards. Opus's revision-2 observer then rejected a newly observed passive thinking-estimate event before assistant/file-action output; the declared revision-3 primary preserved that abort separately. Passive estimates are not final billed usage.

Later host work encountered a real transient audit-file double-link and a concurrent policy-check race during atomic replacement. The second link's producer remains unknown. Study-local revision 5 used physical audit/staging storage, serialized host operations/checks and drained pending checks. Offline qualification included 37 tests and 100 synthetic writes with concurrent checks. The path/link guard stayed strict.

Recovery mechanically applied the original complete Write/Edit actions in a fresh workspace, with the original brief, rubric, capabilities and 45-minute clock. There was no quality regeneration or lead QA feedback. Preserved setup/observer/host failures receive no model-quality penalty, while their operational burden remains visible. These corrections do not establish a general native CLI continuation fix or a new shipped runtime feature.
