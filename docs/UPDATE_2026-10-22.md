# October 22, 2026: Gemini completion and timeout repair

Gemini's reviewer and designer agents exposed the CLI's `finish` completion protocol while their instructions prohibited all tool use. The runner prompt repeated that prohibition. The Gemini instructions now explicitly permit `finish` only to submit the required structured response; file, browser, command, delegation and other operational tools remain forbidden. Response validation and the existing completion-only exception are unchanged.

A diagnostic on Antigravity 1.4.5 used one synthetic arithmetic assertion, Gemini 3.8 Flash High, high effort and a 180-second worker deadline. Before the clarification, it returned no usable answer after 183.736 seconds. The CLI exited zero and reported `SUCCESS`, but its response was empty and stderr disclosed a print timeout with partial output. After the clarification, a new synthetic check on the same assertion, provider, model, effort and deadline completed with an approved structured review in 17.428 seconds. The failed attempt remains part of the evidence. Neither original project was replayed.

This before/after check supports the instruction conflict as a contributing cause; it is not a controlled service-latency benchmark or proof that every historical timeout had the same cause. The two preceding operational failures used CLI 1.4.4. Historical benchmark outcomes, model assignments and scores remain unchanged.

The runner now treats the CLI's explicit print-timeout/partial-output warning as a timeout even when exit code zero and a terminal `SUCCESS` are present. It cannot publish that partial response as a completed review. This fixes a misleading error path without increasing deadlines, retrying failed work, changing provider, enabling credits or weakening permission controls.
