## Runtime

Builder 1.0.6 builds on the already published design capture correction: file-design native streams are bounded at 32 MiB, while the legacy bridge remains at 8 MiB. This metadata budget is separate from artifact and completion limits.

The final design receipt has exactly `summary` and `uncertainties`. The worker is instructed to produce raw JSON, with shared declared limits: summary 4,096 JavaScript string characters, at most 16 uncertainty strings of 512 characters, and 16,384 original UTF-8 bytes overall. Whitespace and an optional exact single lowercase `json` Markdown fence count toward the byte budget. The receiver tolerates that one complete fence; arbitrary surrounding prose, multiple/unlabelled/incomplete fences, malformed JSON, extra keys and oversized fields fail closed. No JSON repair, inference retry or provider switch is added.

Original receipt content is screened in the live event callback before stdout redaction. The process helper also screens a final unterminated stdout line at normal EOF, preserving earlier timeout/cancellation/output-limit precedence. This closes a reproduced synthetic case where redaction could shrink an oversized token-like summary below the downstream cap. Diagnostics do not echo receipt contents. Direct/injected decoding retains the same validation. Existing CLI arguments, selected-file restrictions, exact design identity, subscription/overage proof, physical-path/link checks, candidate verification and deliberate promotion remain intact.

Focused boundary and actual child-process fixtures cover LF/EOF endings, raw UTF-8/whitespace/fence budgets, field/schema limits, malformed JSON, redaction-shaped synthetic content and stop precedence. Independent review found the integration bypass, then verified its correction. These are software tests; they do not make old failed native results successful or establish model design quality.
