## 2026-10-21 - Who sent a reviewer, in the local display

Status: Implemented locally. Distribution: Local read-only display; not in portable preview. Date: Implementation recorded.

The author's local observation display now places a reviewer run in the room of the lead session, Codex or Claude Code, whose own `run` or `dispatch` command named that reviewer's packet. Packet paths already carry the task id, so no field was added to run records. The task id is read only from the argument right after `run` or `dispatch`. Command evidence overrides the display's configured default room only when it exists; titles and recency are never used.

## 2026-10-21 - Plain activity labels in the local display

Status: Implemented locally. Distribution: Local read-only display; not in portable preview. Date: Implementation recorded.

Each agent in the display gets a job label (research, build, test, design pass, red team and others), one current line, and per-turn lines such as "Edited 3 files" or "Tested 2 times: 1 passed, 1 failed". Claude Code sessions and their subagents appear beside Codex tasks and TeamLoop reviewers. Everything is worked out from records the tools already keep: helper names, short command classes, changed file names, search queries cut to 60 characters, reviewer assignments and verdicts. No model call summarizes anything. Prompts, user messages, reasoning, tool output and file contents are never shown. A public case study of the display is [The Dream Machine](https://starforge-dream-machine.netlify.app/).
